`logs/media-marketing/weekly/*.md` from the past month first.

1. **Report the month's numbers against targets** stated in the current
   build-sequence phase (see the teardown's §5 phases and the MMA build
   prompt's phase targets — Phase 0 is proof/$0, Phase 1 is 10 clients /
   $3-8k/mo via 1:1 coaching, etc.). State plainly which phase the data
   actually supports being in — don't assume progression just because a
   month passed.
2. **Name what's working** — the pillar/hook/format combination with the
   real evidence behind it, not a vibe.
3. **Name what should be cut** — a pillar or format underperforming
   across the whole month's sample, or a cadence that's producing 3+
   floor days weekly and should drop per `CLAUDE.md` rule 6.
4. **Recommend the next phase, or recommend staying**, per the build
   sequence — and if asked (by Nolan or by drift in this conversation)
   to skip a phase or launch something premature, **push back explicitly**
   per `CLAUDE.md` rule 3, citing the specific rule and why the current
   data doesn't support skipping.
5. **Scope-creep check** (`CLAUDE.md` rule 7): ask plainly whether content
   work has expanded past the time budget's design intent this month.
6. Write no new log file for this — `/gate` is a synthesis of existing
   weekly logs, output directly to Nolan, phone-readable, one screen if
   possible. Lead with the phase recommendation, not the numbers.
